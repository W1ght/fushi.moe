[Galgame 怎么接进 Fushi？](/faq/galgame)讲的是怎么用；这篇回答更底层的几个问题：Fushi 是怎么把台词从游戏里拿出来的、为什么只能在 Windows 上、到底支持哪些引擎、支持到什么程度，以及「在游戏画面里直接点字查词」是怎么做到的。

先说结论：**文本 Hook 只在 Windows 上做**，而且「支持」分好几个等级——下面的引擎列表照抄 Fushi 仓库里的引擎支持清单（`native/galgame_hook/engine-support.yaml`），没在真实游戏上验证过的，一律写「未验证」。

## 原理：注入 helper + LunaHook + 引擎适配

当你点 **启动并捕获**（或对已运行的游戏点 **附着并捕获**）时，Fushi 做的事情大致是：

1. **拉起一个隔离的注入器**：注入用的组件是单独构建的 x86 / x64 两套 helper（注入器 exe + Hook DLL），**不链接进 Fushi 主程序**，主程序只把注入器当子进程启动。两套 helper 在构建时就随 Windows 安装包一起放进程序目录，运行时不会再去网上下载任何组件。32 位游戏用 x86 那套，64 位游戏用 x64 那套，Fushi 按游戏自动选。
2. **把 Hook 注入游戏进程**：helper 里带着开源的 LunaHook（取自 [LunaTranslator](https://github.com/HIllya51/LunaTranslator) 的发布版，和 Fushi 一样是 GPLv3），负责通用的文本抓取——它认识大量引擎的文本函数，抓到的文字按「文本线程」分开，所以第一次要在会话面板里选那条干净的台词线程。
3. **按引擎适配补齐其他能力**：LunaHook 只管文字。逐句语音、游戏内查词要靠 Fushi 针对每个引擎写的适配：从游戏的语音资源包或解码器里拿到**这一句**的原始语音，或者在引擎的音频输出（XAudio2 / DirectSound）处截取 PCM；都拿不到时才退回录制系统混音（Loopback，会混进 BGM 和音效）。
4. **通过共享内存回传**：helper 把台词、语音、状态写进共享内存，Fushi 主程序读出来配对成「这句台词 + 这句语音 + 这一刻的截图」，在台词浮窗里给你点字查词、一键制卡。

引擎识别靠的是**引擎自己的结构特征**（导出函数、插件接口、运行时模块、资源包格式等），而不是游戏的文件名或标题。所以同一个引擎的其他游戏通常能一起受益；反过来，同引擎的新版本或加壳版改了结构，也可能需要单独适配。

## 为什么只支持 Windows？

Galgame 绝大多数是 Windows 程序，文本 Hook 的本质是把代码注入游戏进程、拦截它的函数调用——这只能在游戏运行的那台 Windows 电脑上做。Fushi 的 Hook、helper、引擎适配都只做 Windows（x86 / x64），Android、iOS、macOS、Linux 上没有文本 Hook，也不宣称支持。

想在手机或 iPad 上玩：游戏和 Hook 留在 Windows 电脑上，用**游戏串流**把画面、声音和台词推到手机上查词制卡，见[能不能在手机 / iPad 上玩电脑里的 Galgame？](/faq/game-streaming)。

## 支持哪些引擎？按清单的实际状态

清单对每个引擎分四个等级：

- **已验证**：在真实游戏的原始启动路径上验证过列出的能力，只覆盖记录在案的版本和能力；
- **部分验证**：至少一条采集路径真机验证过，但还有关键能力受限或未验证；
- **已实现、未验证**：代码已经有了，但没有足够的真实游戏证据，**不能算支持**；
- **不可用**：当前没有实现。

**已验证**（清单里的「verified」）：

- **SiglusEngine**：在 anemoi 正式版（x86）上验证了逐句语音（koe 目录 OVK 语音包里的原始 Ogg，与源文件逐字节一致）和 DirectSound 采集；文本抓取与游戏内查词这两项本身仍标为未验证。
- **Unity IL2CPP**：在 manosaba（x64）上验证了 LunaHook 通用文本、TextMeshPro 文本事件和 AudioClip 语音资源配对。Unity Mono 是另一条，见下面。
- **XAudio2 / DirectSound 通用采集**：不是一个引擎，而是通用的音频截取层，在 KiriKiriZ 和 Siglus 样本上采到过非静音 PCM。注意它截到的可能是软件混音后的整路声音，不一定是干净人声。

**部分验证**（「partial」）：

- **KiriKiri2 / KiriKiri Z**：通用采集到了 PCM，但验证样本把语音、BGM、音效混在一路输出里；资源包与解码器的 Hook 在官方体验版上装上了，但还没走过一句有配音的台词，**不宣称干净的逐句语音**。
- **TyranoScript / NW.js**：在免费全语音作品「かえりみち」（x64）上，导出的逐句语音与游戏资源逐字节一致；只认 `data/sound/v_*` 约定的 OGG / M4A，自定义语音目录或加密包不在内。
- **Artemis Engine（PF8）**：在「アマナツ 体験版」（x64）上验证了 PF8 包里 `sound/vo` 的 Ogg 语音；PF6 解析已实现但没有真实样本跑过。
- **CatSystem2（KIF / INT）**：在官方「CatSystem2 入門セット」用本地生成的语音验证了未加密 `pcm_*.int` 里的 Ogg；带 `__key__.dat` 的加密商业包会被主动拒绝，不对商业作品做语音声明。
- **QLIE（FilePack）**：在「美少女万華鏡 -理と迷宮の少女- 体験版」（x86）上验证了按声源分开的解码后 PCM；只覆盖测过的那个版本。

**已实现、未验证**（「implemented_unverified」，代码在、证据不够，不算支持）：elf AI6、RealLive / 旧 VisualArt's、CMVS（Purple Software）、Ren'Py / FFmpeg、BGI / Ethornell、Malie System（LIBP）、Leaf / AQUAPLUS（只有 WHITE ALBUM2 一个精确配置，不代表整个厂牌）、HUNEX GGE、smash / fzmedia（TYPE-MOON）、M2 wind3d11（STEINS;GATE RE:BOOT）、Unreal Engine（IoStore）、AOS / SFA、Unity（Mono）、YU-RIS、FVP、工画堂 Hy 引擎、LucaSystem。

**不在清单里的引擎**：LunaHook 的通用文本抓取照样会尝试，很多游戏也能出字，只是没有专门的语音和查词适配，语音会退回通用采集或系统混音。抓不到字时可以试 **特殊码**（H-code），用法见[Galgame 怎么接进 Fushi？](/faq/galgame)。

## 查词卡怎么在游戏画面里弹出来？

除了台词浮窗，Fushi 还在做 **游戏内查词**：不看浮窗，直接点游戏画面里的字，查词卡就弹在游戏画面上。难点有两个：

1. **知道每个字在屏幕上的位置**（几何）。来源有三种：引擎运行时的排版信息、引擎内部精确的文字布局，以及**手动校准**——在会话面板的「游戏内查词」里点 **校准**，按提示在游戏里依次点第一个、中间、最后一个字，Fushi 记下正文框和字格。游戏内查词**不使用 OCR**，目前只支持横排正文。模式有「自动 / 仅校准层 / 仅原生几何 / 关闭」。
2. **点字查词时不能推进游戏**。点游戏画面本来就是「下一句」，Fushi 的「输入盾」要在查词那一下把点击拦下来；拦不全的游戏，裸左击可能同时推进台词或触发选项，面板上会标出点击风险。

查词卡本身是 Fushi 渲染的：有的引擎（如 KiriKiri）由 Hook 把卡片画进游戏自己的图层，其他情况是盖在游戏窗口上、不抢游戏前台的 Fushi 窗口。触屏点按、长按、滑动也要同样不推进游戏、不抢前台，这是适配验收的必测项。

**如实说明现状**：清单里所有引擎的游戏内查词（几何、输入盾、点击风险）目前都还是「已实现、未验证」。也就是说它可以试，但没有哪个引擎能保证点字一定不推进剧情。稳妥的做法仍是台词浮窗查词，或者先存档再试。

## 「适配成功」怎么算？

Fushi 对一款游戏「适配成功」有明确标准，在用户真实的启动路径上**四条同时满足**才算，缺一条只算部分适配：

1. **文本**：能 Hook 到当前台词正文，选定的线程是干净正文；
2. **音频**：能拿到和这一句对应的语音（引擎资源或引擎 PCM，纯系统混音不算）；
3. **游戏内查词**：游戏画面内能弹出 Fushi 查词卡；
4. **点击查词不推进**：用鼠标和 Windows 触屏点字查词，都不会推进游戏进度。

适配也只做**引擎级**：某款游戏出问题，修的是它所属引擎的通用判据，不为单个游戏写死特判。所以你的游戏不工作时，最有用的信息是**引擎名、游戏版本、32/64 位、从哪里启动**，通过[应用内反馈](/faq/feedback)发过来。

常见故障（注入被杀软拦截、权限、位数不匹配、乱码）的处理见[Galgame 怎么接进 Fushi？](/faq/galgame)的「常见状况」；Windows 版下载见[下载页](/zh-cn/download)。

看番学日语，最理想的组合是「生肉 + 日语字幕」：字幕能点词、能制卡，卡上带这一句的原声和画面。可不少视频根本找不到日语字幕——冷门老番、日剧、综艺、YouTube 下下来的访谈、自己录的课程。Fushi 的办法是让设备自己「听」一遍：用本机的语音识别（ASR）模型把整集台词转成一份带时间轴的文字字幕，之后就和普通外挂字幕一样用。

先说结论：**能做，全部在你的设备上跑，不上传任何音频**；代价是第一次要下载模型、转一集要花一些时间，准确度比不上人工字幕。找得到现成字幕时，先去[找现成的字幕](/faq/subtitle-download)，那个更快也更准；找不到再转录。

## 在播放器里一键生成字幕

1. 打开视频，进播放器的 **字幕** 菜单（字幕轨那一组）。
2. 点 **语音识别生成字幕**（副标题写着「生成可查词、制卡的文字字幕」）。
3. 弹出的 **设备端语音转录** 面板里：
   - **语音语言**：选视频里说的语言，看番就选日语。选错语言转出来是乱码，这是最常见的失败原因；
   - **模型**：每种语言默认给一个模型，下拉里写着它是「专用模型 · 这门语言识别最准」还是「通用模型」、适合手机还是桌面、要下多大；
   - **加速**：默认「自动（有 GPU 则用）」，也可以选「仅 CPU」。
4. 模型没下载时点 **下载模型**，下完点 **开始转录**。面板上显示进度、已用时间、预计剩余时间和相对实时的倍速。
5. 转完后这份字幕会作为外挂字幕自动挂上并选中，字幕轨列表里多出一条。点字幕上的词就能查，点加号就能[制卡](/faq/first-card)。

转录中途可以点 **暂停**，进度存在检查点上，之后回来点 **继续转录** 接着跑，不用从头再来。转出来的字幕按集保存，下次打开这一集还在。

入口在哪些视频上出现：本地视频文件都有；通过 [Fushi 互联](/faq/interconnect)看另一台设备上的视频时也有——由那台主机把整集音轨裁出来传给你，再在本机转录。纯网络流（直链、YouTube、在线视频源）拿不到完整音轨，没有这个入口。

## 模型要下多大、放在哪

模型按语言分包，只下你要用的那门语言：

- **日语**用 ReazonSpeech 的 k2-v2 模型，是日语专用模型。手机和没有可用显卡的电脑跑的是 int8 量化版，整套约 160 MB；Windows 上有可用的 GPU 时会用 fp32 版，编码器本身就有约 590 MB。
- **英语、普通话、粤语、韩语、俄语、越南语、泰语**各有一个专用模型。
- **德语、西班牙语、法语、意大利语、荷兰语、葡萄牙语、土耳其语、印尼语、阿拉伯语**共用一个通用多语言模型（Omnilingual，约 1 GB 级别），覆盖广但单语言精度不如专用模型，面板里会标「大模型 · 建议桌面（有独显更好）」。

已下载的模型在 **设置 → 存储 → 语音识别模型** 里管理：每种语言显示「已下载 · 占用 xx」「未下载 · 需要 xx」或「已下载一部分」，不用的可以删掉释放空间，下次转录这种语言时再自动提示下载。模型文件下坏了读不出来时，Fushi 会自动清掉并提示重新下载。

会自己折腾模型的用户，面板里还有 **手动指定模型…**：选一个放着 sherpa-onnx 导出模型的文件夹（encoder / decoder / joiner 三件套，或单个 CTC 模型，外加 tokens.txt），文件留在原处不复制。

## 转一集要多久

取决于设备和加速方式，大致规律：

- **Windows + 独立显卡**：自动模式会用 GPU（DirectML）跑 fp32 模型，这是最快的组合；面板上会写「运行于 …」告诉你实际用的是 GPU 还是 CPU，GPU 不可用时会提示已回退到 CPU；
- **macOS / 没有显卡的 Windows / Linux**：自动模式走 int8 + CPU，速度够用；macOS 上加速里另有一个 **CoreML（FP32）** 选项，实测在日语模型上不一定比 CPU 快，默认不用它；
- **Android / iOS**：日语轻量模型手机也能跑，但慢不少，也更耗电发热，建议插着电、放着让它跑。通用多语言大模型在手机上会标「大模型 · 手机上能跑，但很慢」。

面板上的「$speed 倍速」就是当前速度相对音频时长的倍数，看一眼就知道要等多久。

在 iOS 26 / macOS 26 上，模型列表里还会多一个 **系统语音识别（Apple）**：用系统自带的语音模型，不下 Fushi 那份模型，但系统第一次用某种语言时仍会下它自己的语言资产（由系统保管、多个 app 共用）。这个引擎在文件中途没法暂停，停止会丢掉当前文件的进度。

## 准确度怎么样、哪些情况会差

语音识别不是人工听写，期望要放对：

- **对白清楚、BGM 不吵**的段落（日常番、日剧、访谈、播客式内容）准确度高，日常词汇基本都对，拿来点词制卡完全够用；
- **背景音乐和音效很重**的段落（战斗、OP / ED、插入曲）容易漏句或出错字；
- **多人同时说话、喊叫、方言、口齿含糊**的台词也会差一些；
- 人名、专有名词、生造词经常写成同音的别的字——这类词查词本来就查不到，影响不大；
- 歌曲部分基本不要指望。

几条实用建议：

- **语言一定选对**，选错是最常见的「转出来全是乱码」原因；
- 双语音轨的蓝光 / 剧场版，先在播放器里切到日语音轨再转录，Fushi 转的是当前选中的那条音轨；
- 制卡前看一眼字幕里这句和你听到的是否一致，有错字就在卡片编辑里改掉再存，别把识别错误背进脑子里；
- 转出来的字幕时间轴是按语音切的句，句子长短和人工字幕不同，这是正常的。

## 已经有字幕、只是时间对不上？用「重定时」

如果你手里有一份日语字幕，只是和这个视频版本的时间对不上（BD 与 WEB 剪辑不同、帧率不同导致越往后越偏），不需要整份重新转录。字幕菜单里的 **用语音模型重定时** 会听一遍这一集，用识别结果当参照逐句修正时间，**正文和顺序一个字不动**，结果另存成一份新字幕，原文件不改。只有很少句子对上时会提示「检查语音语言是否选对、这份字幕是不是这一集的」。更多对轴办法见[字幕和画面对不上怎么办](/faq/subtitle-sync)。

## 有声书也能用同一套转录

同一套设备端转录也用在有声书上：导入有声书时字幕来源可以选「设备端转录生成字幕」，转出来的字幕用来和正文对齐、逐句高亮，见[有声书怎么用](/faq/audiobook)。

还没装 Fushi 的话，从[下载页](/zh-cn/download)获取，Android、iOS、Windows、macOS（Apple Silicon）和 Linux 都支持设备端转录。

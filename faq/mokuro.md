如果你在日语学习社区里找过「漫画怎么查词」，大概率听说过 mokuro。这篇讲清楚它是什么、`.mokuro` 文件里装的是什么，以及 Fushi 里和 mokuro 相关的三件事：导入现成的 `.mokuro`、调用你自己装的 mokuro 命令行、浏览内置的 Mokuro 目录。

## mokuro 是什么？

[mokuro](https://github.com/kha-white/mokuro) 是一个开源的命令行工具：你给它一个装着漫画页图的文件夹，它在电脑上逐页检测对话框、识别里面的日文，然后输出识别结果。用浏览器打开它配套的阅读器，就能在漫画图片上选中文字，再用 Yomitan 之类的浏览器查词工具查词。

它的意义在于把「漫画是图片、字选不了」这个门槛拆掉了。代价是要在电脑上装 Python 环境和模型、整卷跑一遍识别，而且识别结果和查词、制卡是几样分开的工具。

新版 mokuro（v0.2 起）把一卷的识别结果写成一个 `.mokuro` 文件，本质是一份 JSON：记录每一页的尺寸、每个文字框的位置、是不是竖排、框里每一行的文字。页图本身不在里面，通常放在与 `.mokuro` 同名的文件夹里，两样合起来才是完整的一卷。

## Fushi 怎么读 .mokuro？

Fushi 的漫画阅读器内部就用 mokuro 的数据格式：不管文字是 mokuro 识别的、还是 Fushi 自己的漫画 OCR 识别的，结果都落进同一种结构，阅读器据此在图上叠一层看不见的文字，**点字即查词**，点加号制卡（卡上带对话框那一整句和这一页的画面，详见[本地漫画怎么导入](/faq/manga-local)）。

导入现成的 mokuro 卷：底栏 **漫画** → **导入** → **导入漫画**，然后任选一种方式：

- **选那个 `.mokuro` 文件**：Fushi 按 `.mokuro` 里记录的路径去找旁边的页图；
- **选装着 `.mokuro` 和页图文件夹的那个文件夹**：文件夹里正好一个 `.mokuro` 时，按这一卷导入，OCR 结果一起带上——不会被误当成普通图片文件夹而把文字丢掉；
- **选一个装着多卷的文件夹**：直接子层有多个 `.mokuro` 时，按批量导入逐卷各导一本，每卷带各自的 OCR；
- **CBZ / ZIP 加同名 `.mokuro`**：`book.cbz` 旁边放着 `book.mokuro` 的布局也认。

**iOS 上要注意**：iOS 单选一个 `.mokuro` 文件时带不上它旁边的页图（系统只给你那一个文件的访问权）。请选整卷文件夹（含 .mokuro 和它的页图文件夹），或者把整卷打包成 .zip / .cbz 再导入。

页图对不上时 Fushi 不会静默导出一本没字或缺页的漫画，而是报出具体哪一页找不到图，方便你检查文件夹结构。导入后如果你又对这卷跑了一次识别，OCR 向导会提醒「本卷每一页都已有 OCR 数据，无需再跑（重跑会覆盖现有数据）」。

## 不用 mokuro 也能识别：Fushi 自带漫画 OCR

很多人以为在 Fushi 里读漫画必须先用 mokuro 处理，其实不用。Fushi 自带 **漫画 OCR**：在 **设置 → 漫画 → 漫画 OCR** 下载本机模型后，导入任何 CBZ / ZIP / PDF / 图片文件夹都能在阅读器里直接识别，结果同样存成 mokuro 格式，下次打开不用重跑。识别在本机进行，五个平台都能跑默认的本机模型；手机算力不够的话还能把识别交给已配对的 Fushi 互联服务端（见[Fushi 互联](/faq/interconnect)）。各引擎的差别和调优见[漫画 OCR 认不准怎么办？](/faq/manga-ocr-tips)。

所以 mokuro 在 Fushi 里更像一个「可选的外部引擎」和「现成数据的来源」：你以前用 mokuro 处理过的漫画库，可以原样搬进来继续用。

两条路怎么选，可以按这几点判断：

- **只在手机或平板上读**：用 Fushi 自带的识别就够了，不需要电脑，也不用先整卷跑完——「打开即识别」会从你当前看的那页开始识别，边读边出字；
- **已经有一整个用 mokuro 处理过的库**：直接导入 `.mokuro`，几百卷也不必重新识别；
- **对某个识别器的效果有偏好**：桌面端可以在自带模型和外部 mokuro 之间切换着试，同一卷识别过的结果会覆盖成新引擎的结果；
- **不想反复识别**：不管用哪个引擎，识别结果都存进这本漫画自己的数据（mokuro 格式），之后打开就是带字的，只有你主动「重新识别本卷…」才会再跑。

## 在 Fushi 里调用你装的 mokuro（仅桌面）

已经在电脑上装好 mokuro、习惯它的识别效果的话，可以让 Fushi 直接调用它：

1. **设置 → 漫画 → 漫画 OCR** 的「外部工具」分组里，填 **外部 mokuro 命令行路径**；留空则自动探测（先看环境变量 `FUSHI_MOKURO`，再找 PATH 上的 `mokuro`）；
2. 点 **检测**，显示「已检测到：版本号」就说明找到了；
3. 把 **默认 OCR 引擎** 改成 **外部 mokuro**（「调用你自己安装的 mokuro 命令行，仅桌面可用」）。

之后用 OCR 导入向导或阅读器的「识别本卷」时，Fushi 会对图片文件夹跑 mokuro，拿到 `.mokuro` 产物再导入。常见报错都有明确提示：「未找到 mokuro 可执行文件」「mokuro 长时间无输出，已超时终止」「mokuro 以非零退出码结束」「mokuro 运行完成但未找到 .mokuro 产物」，按提示检查路径和 mokuro 本身能不能在命令行里跑通即可。

## 内置 Mokuro 目录：直接下载带 OCR 的卷

漫画来源里有一个 **内置 Mokuro 目录**（默认站点是 mokuro.moe 的目录），里面是社区整理好、已经附带 `.mokuro` OCR 数据的漫画：

1. **浏览 → 来源**（漫画库的「来源」子标签也一样）选「漫画」，打开 **内置 Mokuro 目录**；
2. 用「搜索系列」找到作品，勾选想要的卷，点 **下载所选**；
3. 每卷分三步：「下载 OCR 数据…」→「下载卷包…」→「解包中…」，大的卷包支持断点续传，服务端临时故障会自动重试；进度在下载队列的「漫画目录下载」里看，完成后显示「已入库」。

下完直接读、直接点字，不需要再识别。这一行和扩展提供的漫画源在同一个列表里，左侧开关关掉后它就不出现在「浏览」里；目录站点地址可以在 **设置 → 漫画** 的「在线目录」分组里改（「在线目录地址」，留空即默认站点）。

**平台限制**：内置 Mokuro 目录属于在线漫画源，**iOS 版按 App Store 规定没有这个功能**（和 Mihon 扩展源一样），Android、Windows、macOS、Linux 可用。iOS 用户仍然可以在电脑上准备好 `.mokuro` + 页图，打包成 CBZ / ZIP 后导入 iPhone / iPad 阅读，见[iOS 版少了哪些功能？](/faq/ios-limits)。

还想找更多在线漫画来源，看[Mihon / Aniyomi 扩展是什么？](/faq/mihon)和[在线看漫画](/faq/manga-online)。
